Tipe Data (Fundamental)

```
Tipe Contoh Dipakai untuk
INT 123 ID, jumlah, counter
VARCHAR 'Andi' Nama, teks fleksibel
DATE 2024-01-01 Tanggal saja
DATETIME 2024-01-01 10:00 Log, transaksi
BOOLEAN true / false Status (aktif/tidak)
DECIMAL 10000.50 Harga, uang (presisi penting)
INT
Jangan pakai buat data yang bukan angka matematis (contoh: nomor HP ❌)
VARCHAR
Fleksibel, tapi jangan kebanyakan → bisa berat
DATE vs DATETIME
Kalau butuh jam → pakai DATETIME
Kalau cuma tanggal → DATE
DECIMAL
Jangan pakai FLOAT buat uang → bisa error pembulatan
```

Salah pilih tipe data = bug + performa jelek

Constraint (Penjaga Data)

```
Constraint Fungsi Contoh
PRIMARY KEY Unik + identitas utama NPWP, ID
FOREIGN KEY Relasi antar tabel user_id → users.id
NOT NULL Wajib ada nilai nama tidak boleh kosong
UNIQUE Tidak boleh duplikat email
CHECK Validasi nilai umur > 17
PRIMARY KEY
Satu baris = satu identitas. Tanpa ini, data lo gak bisa dibedain.
FOREIGN KEY
Jaga relasi tetap valid. Data yatim = tanda FK lo gagal.
NOT NULL
Hindari data kosong yang bikin logic kacau.
UNIQUE
Cocok buat email, username, dll.
CHECK
Validasi di level database (bukan cuma di aplikasi!)
``` 
CREATE TABLE users (
  id INT PRIMARY KEY,
  email VARCHAR(100) UNIQUE,
  nama VARCHAR(100) NOT NULL,
  umur INT CHECK (umur > 17)
);

Tanpa constraint = data bebas rusak tanpa kontrol

Cara Baca Query

SELECT nama
FROM users
WHERE umur > 30;

Eksekusi: FROM → WHERE → SELECT

Query Fundamental (Yang Wajib Dikuasai)

```
1. SELECT
Ambil & bentuk data
2. WHERE
Filter data
3. ORDER BY / LIMIT
Urutkan & batasi hasil
4. JOIN
Gabung data antar tabel
5. GROUP BY
Ringkas data (aggregate)
6. HAVING
Filter hasil grouping
``` 
SELECT u.nama, SUM(o.total) as total
FROM users u
JOIN orders o ON u.id = o.user_id
WHERE o.total > 50000
GROUP BY u.nama
HAVING SUM(o.total) > 100000
ORDER BY total DESC
LIMIT 5;
```
```

Cara baca query (yang sering kebalik):

FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER → LIMIT

Kalau lo gak ngerti urutan ini, lo bakal salah logika terus
